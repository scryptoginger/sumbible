# SumBible

Chapter-by-chapter summaries of the Bible and the LDS Standard Works, informed by Hebrew, Greek, and multi-translation insight. (powered by AI)

**Live site:** [sumbible.vercel.app](https://sumbible.vercel.app) (note: link does NOT open in new tab automagically)

## What this is

SumBible is a public reference site. For each chapter of scripture it covers, it
offers two summaries: a short "highlight reel" of what the chapter is really
doing, and a deeper summary that draws on the original languages, the structure
of the text, cross-references, and the places where translations and traditions
read a passage differently.

It covers the Protestant 66-book Bible and the Latter-day Saint Standard Works
(Book of Mormon, Doctrine and Covenants, Pearl of Great Price). It **does not**
reproduce the text of scripture — every chapter links out to canonical online
editions, and quotes no more than a verse or two for context.

The guiding principle is **accuracy over coverage**: a few well-sourced chapters
are worth more than a thousand hallucinated ones. See [`AUTHORING.md`](./AUTHORING.md)
for the full content contract.

## Tech stack

- **[Astro 6](https://astro.build)** — static site generator
- **MDX** — chapter content, so custom components embed inline
- **Tailwind CSS 4** — via the `@tailwindcss/vite` plugin
- **Astro Content Collections** — Zod-typed chapter metadata
- **`@astrojs/vercel`** — static-output adapter; deployed on **Vercel**
- **TypeScript** throughout

> Note: the project was specified against Astro 5, but `create-astro` now
> installs Astro 6. Astro 6 supports the same Content Layer API, MDX, Tailwind,
> and Vercel adapter, so the project runs on Astro 6.

## Local development

Requires Node 20.3+ or 22+ (see `.nvmrc`; Node 22 recommended).

```sh
npm install         # install dependencies (also installs the git hooks)
npm run dev         # start the dev server (http://localhost:4321)
npm run build       # build the static site (prebuild index + astro + pagefind)
npm run preview     # preview the production build locally
npm run lint:content # content-discipline checks
npx astro check     # type-check + validate content collections
```

Search and OG images only exist after a full `npm run build`, so use
`npm run preview` (not `npm run dev`) to exercise them.

## Adding a chapter

A chapter is a single `.mdx` file under `src/content/chapters/<canon>/<book>/`.
Filenames and folder names are organizational only — routes are generated from
the **frontmatter**, not the file path.

1. Scaffold the file with `npm run new-chapter` (see below) — never freehand
   the frontmatter.
2. Fill in `highlightSummary`, `externalLinks`, and `sources`.
3. Write the deep summary in the MDX body. The `<LangNote>`, `<LangNotes>`,
   `<TranslationCompare>`, `<VerseRef>`, and `<ScriptureBlock>` components are
   available globally — do **not** import them.
4. Run `npm run build`, `npx astro check`, and `npm run lint:content`; the
   chapter appears in navigation automatically.

Read [`AUTHORING.md`](./AUTHORING.md) first — it is the full content contract.

The seven seed chapters are the templates to copy from:

| Chapter | Path | Demonstrates |
| :-- | :-- | :-- |
| Genesis 1 | `bible-ot/01-genesis/01.mdx` | full Hebrew workflow, LangNote + TranslationCompare |
| John 1 | `bible-nt/43-john/01.mdx` | full Greek workflow |
| Romans 8 | `bible-nt/45-romans/08.mdx` | a textual-variant `TranslationCompare` |
| 1 Nephi 1 | `book-of-mormon/01-1-nephi/01.mdx` | no original language; `LangNotes` only |
| 3 Nephi 11 | `book-of-mormon/03-3-nephi/11.mdx` | intertextual notes; `christReferences` |
| D&C 1 | `doctrine-and-covenants/001.mdx` | no content components at all |
| Moses 1 | `pearl-of-great-price/moses/01.mdx` | JST text; Genesis-relationship notes |

## Content workflow

AI-drafted on a feature branch → pull request → human review → merge to `main`
→ Vercel auto-deploys. Each chapter carries a workflow `status`:

- **`draft`** — AI-drafted, not yet reviewed. Shows a "Draft — awaiting review"
  badge. May contain errors.
- **`review`** — under human review. Shows an "In review" badge.
- **`published`** — reviewed and approved. No badge.

Promote a chapter between statuses with `npm run promote-chapter` — never
hand-edit the `status` field.

## Authoring scripts

| Command | Purpose |
| :-- | :-- |
| `npm run new-chapter -- --canon <c> --book <slug> --chapter <n> [--title "..."]` | Scaffold a schema-correct chapter skeleton. |
| `npm run new-book -- --canon <c> --book <slug>` | Scaffold a book-summary skeleton. |
| `npm run new-canon -- --canon <c>` | Scaffold a canon-summary skeleton. |
| `npm run promote-chapter -- --canon <c> --book <slug> --chapter <n> --to <status> [--reviewed-by <name>]` | Flip a chapter's workflow status; stamp timestamps. |
| `npm run lint:content` | Content-discipline checks across the chapter, book, and canon collections. |
| `npm run build-favicons` | Rasterize `public/favicon.svg` to the PNG favicon set. |

## CI & quality gates

- **GitHub Actions** — `.github/workflows/validate.yml` runs `lint:content`,
  `astro check`, and `build` on every pull request and push to `main`. Branch
  protection that makes this a *required* check must be enabled by hand in the
  repository's GitHub settings — the workflow file alone does not enforce it.
- **Pre-commit hook** — installed via `simple-git-hooks` (set up automatically
  by `npm install`); runs `astro check` and `lint:content` before every commit.

## Iconography

SumBible's visual identity uses **symbolic** Christian iconography only — never
figurative imagery. The favicon and header mark are the **chi-rho**, the
ancient Christogram; section dividers carry an **alpha-omega**; the footer
shows an **ichthys**; and each canon has its own emblem (a Hebrew **aleph** for
the Old Testament, the chi-rho for the New Testament and Book of Mormon, a
**cross** for the Doctrine and Covenants and Pearl of Great Price). No
generated or embedded image ever depicts Christ or any divine figure as a
person; the symbolic approach is a deliberate theological choice. Icon
components live in `src/components/icons/`.

## Security

`npm audit` reports a handful of high-severity advisories, all in transitive
build/dev dependencies. SumBible ships **zero server runtime** — it is a fully
static site — so the practical risk is low, and `npm audit fix --force` is
deliberately *not* run because it would introduce breaking changes. Revisit if
the project gains a server runtime or the advisory set changes materially.
